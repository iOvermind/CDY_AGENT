# GLOSSARY.md 撰寫規範

> 本規範規定名詞表 `GLOSSARY.md` **該收什麼詞、怎麼寫**。
> 格式以 `domain-modeling` 技能的 GLOSSARY 格式為準。
> 通用規範，任何專案皆適用。取代舊的 `CONTEXT.md`。

---

## 1. 目的與適用範圍

### 1.1 目的

讓同一個概念在程式碼、文件、issue、使用者介面文字裡**只有一個叫法**。

沒有這份文件時，典型的症狀是：同一個東西在程式裡叫 `Entry`、在 issue 裡叫「知識點」、在畫面上叫「記法」，三個人以為在講三件事；或是 agent 每開一次工作階段就發明一個新詞。

### 1.2 讀者

- 寫程式、寫文件、開 issue 的人。
- 各專案裡的 **AI agent**。`domain-modeling`、`tdd`、`triage` 等技能開工前都會先讀名詞表，照它的詞命名測試、issue 與重構提案。

### 1.3 邊界

名詞表**只回答「這個詞是什麼意思」**：

| 問題 | 文件 |
| :--- | :--- |
| **這個詞是什麼意思、不要叫它什麼** | **`GLOSSARY.md`（本規範）** |
| 為誰做、為什麼做 | `PRODUCT.md` |
| 模組怎麼切、介面是什麼、怎麼建置 | `DEVELOPER.md` |
| 為什麼這樣決定 | `docs/adr/` |
| 遊戲機制、規則清單、數值 | `docs/<主題>.md`（例如 `docs/MECHANICS.md`） |

### 1.4 由哪個技能維護

**`domain-modeling`**（常經由 `/grill-with-docs` 觸發）負責建立與更新本文件：討論中一個詞一確定，就當場寫進來，不累積到最後。人工撰寫時**必須**照本規範的格式，否則技能讀不懂。

### 1.5 強制語彙

| 用詞 | 意義 |
| :--- | :--- |
| **必須** | 不做就是不合規（MUST） |
| **建議** | 有更好的理由才可以不做（SHOULD） |
| **可** | 自行斟酌（MAY） |

## 2. 檔案位置與命名

- 檔名**必須**為 `GLOSSARY.md`，**必須**放在 `docs/`。
- 編碼**必須**為 **UTF-8 無 BOM**，換行**必須**為 **LF**，檔尾**必須**留一個換行。
- 語言**必須**為**繁體中文**；`_Avoid_:` 標記保留原文（技能解析用）。
- **第一個詞確定時才建檔**，**禁止**預先建空檔。
- 條文中提到其他文件時只寫檔名；實際位置見 `DEVELOPER_RULES.md` §1.3 的文件地圖。

### 2.1 一份還是多份

- 一般專案**必須**只有一份 `docs/GLOSSARY.md`，用 H2 分群，**不設長度上限**。
- 只有當儲存庫真的包含多個獨立領域（monorepo 裡各自成立的套件）時，**可**改用 `docs/GLOSSARY-MAP.md` 指向各領域自己的 `GLOSSARY.md`，並寫明領域之間的關係。
- **禁止**只因為檔案變長就拆分——變長通常代表混進了不屬於這裡的東西（§4.4）。

### 2.2 從 `CONTEXT.md` 遷移

舊版技能把名詞表叫 `CONTEXT.md`（`CONTEXT-MAP.md`）。遷移時：

1. 移到 `docs/GLOSSARY.md`（`CONTEXT-MAP.md` → `docs/GLOSSARY-MAP.md`）。
2. 依 §3 改成標準詞條格式，依 §4.2 把主詞改成中文。
3. 依 §4.4 把實作細節搬到該去的文件，名詞表只留定義與連結。
4. 同步修改 `CLAUDE.md` 與 `docs/agents/domain.md` 裡的指向。
5. 刪除舊檔，**禁止**兩個檔名並存。

## 3. 結構

### 3.1 版面

```markdown
# 《<專案名稱>》(<專案代號>)

<一兩句：這個領域是什麼、為什麼存在。>

## <分群一>

**<詞>**（<English>／`<識別字>`）：
<一兩句定義。>
_Avoid_: <不要用的說法>、<不要用的說法>

## <分群二>

…
```

| 部位 | 規定 |
| :--- | :--- |
| H1 | **必須**為專案的顯示名「《專案名稱》(專案代號)」 |
| 導言 | **必須**一到兩句，說明這個領域是什麼 |
| H2 | 詞的分群，以領域裡自然成團的概念命名（「記憶」「交易」），**禁止**用「其他」「雜項」 |
| 詞條 | 依 §3.2 |

所有詞屬於同一個緊密的概念群時，**可**不分群，直接在導言後列詞條。

### 3.2 詞條格式

每個詞條**必須**是三行（`_Avoid_` 沒有可寫時省略第三行），詞條之間空一行：

```markdown
**記憶條目**（Entry）：
玩家記得的一條資訊的最小單位。
_Avoid_: 記法、知識點
```

| 行 | 規定 |
| :--- | :--- |
| 第一行 | 粗體主詞，括號內為英文原文或程式識別字，接全形冒號 |
| 第二行 | 定義，一到兩句 |
| 第三行 | `_Avoid_:` 後列出不要用的同義詞，頓號分隔 |

**禁止**用表格、H3／H4 標題或巢狀清單寫詞條——技能寫入時只會照上面的格式。

## 4. 撰寫規則

### 4.1 只收本專案特有的詞

- **必須**只收這個專案領域裡才有、或在這裡有特定意思的詞。
- 一般程式概念（逾時、錯誤型別、快取、工具函式）**禁止**收錄，即使專案大量使用。
- 加詞前先問：「換一個不同領域的專案，這個詞還是同一個意思嗎？」是的話就不收。

### 4.2 主詞以中文為主

- 主詞**必須**是中文，且是文件、issue、使用者介面裡實際使用的那個詞。
- 括號內**必須**附英文原文或程式識別字（`記憶條目（Entry）`、`遊戲資料夾（GameFolder）`），讓人能從程式碼搜尋回來。
- 定義**必須**為繁體中文。

### 4.3 定義寫「是什麼」，不寫「怎麼做」

- 定義**必須**說明這個概念**是什麼**、與相近概念的差別；**禁止**寫它怎麼被計算、存在哪、由哪個函式處理。
- 一到兩句寫完。寫不完代表這個詞其實是好幾個概念，**必須**拆成多個詞條。
- 詞與詞的關係（「一冊有很多景點」）**可**寫進定義。

### 4.4 實作細節不進名詞表

**可**附上程式識別字以便搜尋；除此之外的實作細節**必須**放到該去的地方，名詞表只留一句連結：

| 內容 | 該去哪 |
| :--- | :--- |
| 檔案路徑、函式名、port、資料欄位 | `DEVELOPER.md` §5 |
| 公式、門檻、平衡數值、規則清單 | `docs/<主題>.md`（例如 `docs/MECHANICS.md`） |
| 為什麼這樣定義、考慮過的替代 | `docs/adr/` |
| 還沒查證、還沒決定的事 | `docs/OPEN_QUESTIONS.md` 或 issue |

### 4.5 `_Avoid_`：要有主見

- 同一個概念有好幾個說法時，**必須**選一個當主詞，其他列進 `_Avoid_`。
- 舊名、程式碼裡的不同叫法、容易混淆的鄰近詞都**建議**列進去，並可在括號說明情境（「`_Avoid_`: 登城章（指所有冊時）」）。
- 發現有人用了 `_Avoid_` 裡的詞，**必須**改成主詞，不是把它加回定義。

### 4.6 何時更新

- 討論中一個詞的意思確定了，**必須**當場寫進名詞表，**禁止**留到工作結束再補。
- 程式碼與名詞表矛盾時，**必須**先釐清哪邊對，再改錯的那一邊。
- 詞改名時，**必須**同步改程式識別字以外的所有文件；程式識別字改不改由 `DEVELOPER.md` 決定，但括號內**必須**寫現在的識別字。

### 4.7 一般撰寫規則

- 全文**只有一個** H1；分群用 H2。
- 庫內連結**必須**用相對路徑。
- 詞條**可**在定義末尾連結 ADR（「見 ADR 0004」），**禁止**複述 ADR 的內容。

## 5. 範例與註解慣例

- 佔位符**必須**用角括號加繁中描述：`<詞>`、`<分群>`。
- 虛構專案一律用 `MYAPP`。

範例（虛構專案 `MYAPP`，一個存檔編輯器）：

```markdown
# 《存檔編輯器》(MYAPP)

讀取遊戲存檔、讓使用者改角色數值、再寫回遊戲的工具。

## 存檔

**遊戲資料夾**（GameFolder）：
使用者選定、含遊戲執行檔與存檔的資料夾；編輯器直接讀寫其中的檔案，不另存副本。
_Avoid_: 安裝路徑、工作區

**存檔槽**（SaveSlot）：
遊戲內一個可讀寫的存檔位置；一個遊戲資料夾有固定數量的存檔槽。
_Avoid_: 存檔（指位置時）、slot
```

## 6. 禁止事項

- **禁止**用表格、H3／H4 或巢狀清單寫詞條。
- **禁止**收錄一般程式概念。
- **禁止**寫入檔案路徑、函式名、公式、門檻、資料欄位等實作細節（程式識別字除外）。
- **禁止**主詞用英文、中文放括號。
- **禁止**沒有主見地並列同義詞。
- **禁止**預先建立空的名詞表，或用「其他」「雜項」當分群。
- **禁止**只因變長就拆檔。
- **禁止**保留舊的 `CONTEXT.md`。

## 7. 檢查清單

- [ ] 檔案在 `docs/`，UTF-8 無 BOM、LF、檔尾一個換行
- [ ] H1 是顯示名，接一到兩句導言
- [ ] 每個詞條都是「粗體中文主詞（英文／識別字）：」＋定義＋`_Avoid_:`
- [ ] 每個詞都是本專案特有的，沒有一般程式概念
- [ ] 定義寫的是「是什麼」，一到兩句
- [ ] 沒有路徑、函式、公式、門檻、欄位等實作細節
- [ ] 同義詞都有選定主詞，其他列進 `_Avoid_`
- [ ] 文件、issue、使用者介面文字用的是主詞
- [ ] 沒有殘留的 `CONTEXT.md`，`CLAUDE.md` 與 `docs/agents/domain.md` 指向 `docs/GLOSSARY.md`
